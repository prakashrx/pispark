# Adopt an existing system

Adopting is a one-time conversion, done only when the person asks. Afterwards the mind replaces the old system; the two don't run side by side.

1. **Read the existing system**: its goals, backlogs, decisions, instructions and notes.
2. **Sort each lasting thing by the tests, in order:**
   - About what the person wants? → **charter**.
   - About how you should behave toward the person (own, tell, ask, never)? → **contract**.
   - Ends when some goal ends (ideas, plans, open work)? → **work**: open goals become cards. Ideas become `idea` cards of one line. Finished work isn't carried over.
   - Can the place tell you this again (code, docs, history)? → **leave it out**.
   - Otherwise → **knowledge**. A repeatable procedure → propose a skill instead.
3. **Write work cards** with `mind_work`. Charter, contract and knowledge go through `mind_record` as proposals (`origin: "inferred"`), each with a short reason naming where it came from.
4. **Report briefly:** how many cards, how many proposals, and what you left out and why. The person accepts proposals with `/mind accept <id>`, or tells you which to keep.

Budgets apply. If a part would overflow, merge and generalise; don't drop the person's own words.
